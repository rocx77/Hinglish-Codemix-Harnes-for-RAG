# Technical Benchmark & Evaluation Specification

## 1. Overview of Evaluation Framework

In a Retrieval-Augmented Generation (RAG) system, downstream LLM generation quality relies entirely on **Retrieval Recall** and **Position Rank**. If the vector database fails to find the relevant background document—or places it too low in the context window—the LLM either hallucinates or fails to answer.

To prove that our deterministic `HinglishPhoneticRAG` middleware solves **Tokenization-Level Representation Drift** without needing expensive LLM translation calls, we evaluate systems using three formal Information Retrieval (IR) metrics across a multi-tier noise benchmark.

---

## 2. Metric 1: Mean Reciprocal Rank ($MRR$)

### Definition

$MRR$ evaluates **how high up** in the retrieved list the *first relevant ground-truth document* appears. In RAG pipelines, position matters significantly because LLMs exhibit an "attention bias" towards documents placed higher in their prompt context.

### Mathematical Formula

For a set of evaluation queries $Q$, where $\vert{}Q\vert{}$ is the total number of queries, and $\text{rank}_i$ is the position of the first correct ground-truth document for the $i$-th query:

$$MRR = \frac{1}{\vert{}Q\vert{}} \sum_{i=1}^{\vert{}Q\vert{}} \frac{1}{\text{rank}_i}$$

* If the correct document is the **1st result** ($\text{rank} = 1$), Reciprocal Rank $= \frac{1}{1} = 1.0$.
* If the correct document is the **2nd result** ($\text{rank} = 2$), Reciprocal Rank $= \frac{1}{2} = 0.5$.
* If the correct document is **not retrieved** in the top candidates ($\text{rank} = \infty$), Reciprocal Rank $= 0$.

---

### Step-by-Step Numerical Example

Suppose our knowledge base contains official university documents ($D_1, D_2, \dots, D_{10}$), and we test **3 Hinglish queries**:

#### **Query 1 ($Q_1$):** `"mra laptop bht lag kr rh h"`

* **Ground Truth Document ($D^*$):** $D_4$ (*"Troubleshooting Hardware Performance & Slow Laptops"*)
* **Retrieved List from Vector DB:** $[D_2, \mathbf{D_4}, D_9, D_1]$
* **Rank of $D_4$:** Position 2 ($\text{rank}_1 = 2$)
* **Reciprocal Rank ($RR_1$):** $\frac{1}{2} = 0.500$

#### **Query 2 ($Q_2$):** `"CSE department ki fees kitni h"`

* **Ground Truth Document ($D^*$):** $D_7$ (*"Fee Structure for B.Tech Computer Science"*)
* **Retrieved List from Vector DB:** $[\mathbf{D_7}, D_3, D_1, D_8]$
* **Rank of $D_7$:** Position 1 ($\text{rank}_2 = 1$)
* **Reciprocal Rank ($RR_2$):** $\frac{1}{1} = 1.000$

#### **Query 3 ($Q_3$):** `"hostel room book kaise kare"`

* **Ground Truth Document ($D^*$):** $D_2$ (*"Hostel Allocation Procedures"*)
* **Retrieved List from Vector DB:** $[D_5, D_8, D_9, \mathbf{D_2}]$
* **Rank of $D_2$:** Position 4 ($\text{rank}_3 = 4$)
* **Reciprocal Rank ($RR_3$):** $\frac{1}{4} = 0.250$

#### **Final $MRR$ Calculation:**

$$MRR = \frac{0.500 + 1.000 + 0.250}{3} = \frac{1.750}{3} \approx 0.583\text{ (or } 58.3\% \text{)}$$

## 3. Metric 2: Hit Rate at $K$ ($Hit@K$)

### Definition

$Hit@K$ (also known as *Recall at $K$*) measures the percentage of queries for which the correct ground-truth document is retrieved **anywhere within the top $K$ results**.

In RAG, $K$ usually equals the number of context documents injected into the LLM prompt (typically $K = 3$ or $K = 5$). As long as the document is inside the top $K$, the LLM receives the necessary context.

### Mathematical Formula

$$\text{Hit}@K = \frac{1}{\vert{}Q\vert{}} \sum_{i=1}^{\vert{}Q\vert{}} \mathbb{I}(\text{rank}_i \le K)$$

Where $\mathbb{I}(\cdot)$ is an indicator function:

* $\mathbb{I} = 1$ if $\text{rank}_i \le K$
* $\mathbb{I} = 0$ if $\text{rank}_i > K$ or document is missing.

---

### Step-by-Step Numerical Example

Using the exact same 3 queries from the previous example, let's evaluate performance at **$K = 1$**, **$K = 3$**, and **$K = 5$**:

| Query | Ground Truth Position ($\text{rank}_i$) | $\text{Hit}@1$ ($\le 1$) | $\text{Hit}@3$ ($\le 3$) | $\text{Hit}@5$ ($\le 5$) |
| --- | --- | --- | --- | --- |
| **$Q_1$** (`"mra laptop bht lag..."`) | Rank 2 | 0 (No) | 1 (Yes) | 1 (Yes) |
| **$Q_2$** (`"CSE department ki fees..."`) | Rank 1 | 1 (Yes) | 1 (Yes) | 1 (Yes) |
| **$Q_3$** (`"hostel room book..."`) | Rank 4 | 0 (No) | 0 (No) | 1 (Yes) |
| **Aggregated Score** | — | $\frac{1}{3} = \mathbf{33.3\%}$ | $\frac{2}{3} = \mathbf{66.7\%}$ | $\frac{3}{3} = \mathbf{100.0\%}$ |

> **Key Insight for Professors:** $\text{Hit}@1$ measures precision for single-shot retrieval, while $\text{Hit}@5$ measures overall system recall safety within a multi-document RAG context window.

## 4. Metric 3: Retrieval Latency ($L_{\text{ms}}$)

### Definition

Retrieval Latency ($L_{\text{ms}}$) measures the total end-to-end execution duration (in milliseconds) from the moment the user submits a raw query string to the moment candidate document chunks are returned from the vector store.

### Mathematical Pipeline Breakdown

End-to-end latency is calculated as:

$$L_{\text{total}} = t_{\text{preprocessing}} + t_{\text{embedding}} + t_{\text{vector\_search}}$$

```
[User Input] ──► ( t_preprocess ) ──► ( t_embedding ) ──► ( t_vector_search ) ──► [Retrieved Context]

```

### 1. Gold-Standard Query-Document Mapping

* We compile $N = 100$ ground-truth English knowledge base documents ($D_1^*, D_2^*, \dots, D_{100}^*$).
* Each document is assigned a set of canonical target queries ($Q$).

### 2. The 3-Tier Noise Generation Matrix

We transform each canonical query into three realistic user typing variations:

* **Noise Level 1 (Clean Transliteration):** Full-length phonetic Romanization (e.g., `"Mera account balance kitna hai"`).
* **Noise Level 2 (Aggressive Shortening):** Vowel-dropped text-speak (e.g., `"Mra acct bal ktn h"`).
* **Noise Level 3 (Typo & Phonetic Drift):** Keyboard typos combined with acoustic variations (e.g., `"Mera acount balence kitanaa he"`).

### 3. Hypothesis to Prove in Paper Results

1. **Baseline A (Raw Query into `BGE-M3`):** High $MRR$ at Noise Level 1, but degrades sharply ($>60\%$ drop) at Noise Levels 2 and 3 due to tokenization mismatches.
2. **Baseline B (LLM Query Pre-Translation):** Maintains high $MRR$ across all noise levels, but suffers from high latency overhead ($+850\text{ ms}$) and monetary API costs.
3. **`HinglishPhoneticRAG` (Our Proposed Method):** Maintains high $MRR$ ($>85\%$) across all noise levels with sub-$5\text{ ms}$ preprocessing latency.
